FINAL CAPSTONE - AI STRATEGY

Cornerstone Relief International (CRI)
Checked: 2026-08-10


1. STRATEGIC POSITION

CRI should become AI-native without becoming AI-dependent.

AI acts as an assistive operating layer for the nine-person IT team, but it
does not replace accountable human judgment.

The architecture separates low-sensitivity productivity workloads from
restricted beneficiary workloads.

Public or general-purpose AI services must never receive beneficiary case
notes, medical information, credentials, donor payment information, or other
restricted data.


2. TOOL THREAD - WHAT CRI USES AI FOR

CRI uses AI as a tool for:

- summarizing infrastructure and security telemetry;
- drafting incident hypotheses and runbook suggestions;
- helping administrators write and review scripts, IaC, and documentation;
- translating and summarizing public or approved internal material;
- natural-language search over approved policy and operational knowledge;
- assisting with ticket classification and repetitive service-desk work.

AI output in this thread is advisory unless an action is specifically allowed
by the autonomy ladder.

AI does not independently authorize wire transfers, modify identity or firewall
policy, accept organizational risk, or make governance decisions.

3. WORKLOAD THREAD - WHAT CRI RUNS

The primary restricted workload is a private beneficiary case-note RAG service.

It returns only records that the authenticated user is already authorized to
view.

Retrieved documents are treated as untrusted data, not as instructions.

The service has no arbitrary external egress and cannot email or export
restricted content without an approved workflow.

Other planned workloads are:

- a small local embedding service;
- model and evaluation jobs;
- AI-assisted operations;
- approved external APIs for low-sensitivity productivity.

CRI does not train a foundation model.


4. MODEL TIERS

TIER A - SMALL / LOW-COST MODELS

Use for classification, formatting, routing, extraction, and simple summaries.

Prefer the smallest model that meets the measured quality target.

TIER C - HIGH-CAPABILITY EXTERNAL REASONING MODELS

Use only through an approved enterprise API for public information,
low-sensitivity organizational data, or de-identified data.

Restricted beneficiary records are prohibited.


EMBEDDING TIER

Employ a small embedding model. Tenants and document ACLs need to be preserved.

Embeddings and vector indexes are considered to be derived sensitive data.


5. BUILD VS BUY VS SELF-HOST

BUY

CRI buys commodity capabilities that a nine-person IT team should not
recreate, including identity services, security tooling, object storage,
backup services, and approved external AI APIs for low-sensitivity workloads.

BUILD

CRI builds the CRI-specific value and control layer, including retrieval
policies, connectors, evaluation suites, approval workflows, data
classification, observability, and governance integrations.

SELF-HOST / PRIVATE

CRI keeps beneficiary case-note RAG on a private controlled inference lane.

This decision is based on privacy, data residency, controlled egress,
auditability, and beneficiary trust.

It is not based on the assumption that the supplied 8xH100 configuration is
cheaper.

7. STANDARDS POSITION

CRI treats durable interfaces as architecture and products as replaceable
implementations.

Preferred contracts include:

- OpenTelemetry for observability;
- OpenAI-compatible inference APIs;
- OCI artifacts for model distribution;
- MCP with least-privilege scopes for agent-to-tool access;
- standard Kubernetes resource APIs.


8. HUMAN JUDGMENT

The final architecture uses a hybrid and deliberately conservative approach.

CRI automates observation and narrow, reversible remediation.

Data deletion, security-boundary changes, model promotion, financial
commitments, and sensitive identity operations remain under named human
control.

This boundary is intentional because CRI handles sensitive information about
vulnerable beneficiaries.
