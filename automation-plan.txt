FINAL CAPSTONE - AUTOMATION PLAN

Cornerstone Relief International (CRI)


1. OPERATING MODEL

AIOps is used by CRI to detect, correlate, diagnose, recommend and
bounded remediation.

The Type of an action is specified prior to allowing execution by an agent.

The decision tests are:

1. Is the action reversible?
2. What is the blast radius?
3. Could it destroy or expose data?
4. Could it weaken a security boundary?
5. Could it create recurring financial cost?
6. How many systems, users, or offices could it affect?

Closed loop:

EVENT -> OBSERVE -> DIAGNOSE -> PROPOSE -> POLICY CHECK ->
HUMAN GATE WHEN REQUIRED -> ACT -> VERIFY UNDERLYING SIGNAL -> AUDIT


2. AUTONOMY LADDER

OBSERVE

Example:
read_observability

The agent can consume the OpenTelemetry metrics, logs, traces, Kubernetes status,
Model telemetry, and GPU telemetry. It is unable to write on external or modify something.
system state. The observation is not only recorded with actor identification but also a UTC
timestamp.

RECOMMEND

Examples:
propose_patch_priority
delete_persistent_volume
modify_firewall_rule

The agent may present evidence and prepare a proposed change, but a human
performs or schedules the action.

Persistent-volume deletion remains at RECOMMEND because it can cause
irreversible data loss.

Firewall changes remain at RECOMMEND because they change a security trust
boundary and can affect multiple systems.

APPROVE

Examples:
scale_deployment
rotate_credential
promote_model_to_production

The agent may prepare the exact action, but a named human must approve it after
the required checks.

Scaling is reversible, but it changes capacity and recurring cost.

Credential rotation is security-sensitive and requires out-of-band identity
verification.

Model promotion requires evaluation, model and data documentation, AIBOM,
privacy and security review, a rollback target, and named human approval.

ACT

Examples:
restart_stateless_pod
rebuild_embedding_index

Only reversible work can be automatic action.

Automatic action is limited to narrow, reversible, low-blast-radius work.

A stateless restart is limited to one pod, is rate-limited, and must be
independently verified.

An embedding-index rebuild creates a new derived index from a signed source
corpus. The new index is validated before the alias is changed, and protected
source documents are never deleted.

4. AUDIT AND VERIFICATION

Every proposal, gate decision, approval, action, verification result, model ID,
human identity, and UTC timestamp is appended to a WORM audit target.

Agents are not allowed to rewrite audit history.

VERIFY checks the original service signal rather than only checking whether a
command returned exit code 0.

A successful command may still leave the service unhealthy, modify the wrong
resource, introduce a security problem, or create an unplanned cost.

5. RULE OF TWO

An unsupervised agent must never simultaneously have:

1. untrusted content;
2. sensitive or private-data access;
3. an unrestricted external or mutating tool.

The restricted case-note RAG must read private data and may retrieve untrusted
text.

Therefore it does not receive an arbitrary outbound communication path.

Sensitive exports and mutating actions must cross a named human gate.

7. ACCOUNTABILITY

The named human approver remains responsible for approval decisions.

The AI agent may collect evidence, prepare an action, and execute only those
narrow actions explicitly allowed at the ACT tier.

The AI agent is never the organizational risk-acceptance authority.
